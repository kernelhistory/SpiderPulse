# Руководство для контрибьюторов // Contributing Guide

Благодарим за интерес к развитию **SpiderPulse OSINT**. Для сохранения целостности архитектуры, безопасности и визуального стиля проекта, пожалуйста, придерживайтесь описанных ниже стандартов.

---

## 01. Принципы разработки и дизайна

1. **Локальная автономность (Local-First)**: В кодовой базе запрещено использование любых сторонних трекеров, аналитических библиотек, рекламных SDK или промежуточных бэкенд-серверов.
2. **Единая дизайн-система (`Graphite Monolith`)**:
   - Интерфейс строится строго на базе Jetpack Compose и Material Design 3 (`Theme.kt`).
   - Цветовая гамма выдержана в строгих графитовых и монохромных тонах (`#0D0D0F`, `#121215`, `#232329`, `#B8B8C2`).
   - В интерфейсе приложения, логах, документации и коммитах **не используются эмодзи**.
3. **Безопасность по умолчанию**:
   - Любые новые данные, сохраняемые на диск, должны проходить через `CryptoManager` (`AES-256-GCM`).
   - Любые сетевые вызовы должны выполняться через защищенный конвейер `OsintEngine` с проверкой SSRF и маскировкой секретов (`CryptoManager.redactSecret`).

---

## 02. Добавление новых встроенных OSINT API модулей

При добавлении нового модуля в `DefaultModules.kt` или `database/spiderpulse_api_database.json` убедитесь, что:

- Конечная точка использует протокол `HTTPS`.
- Если API не требует ключа (`AuthType.NONE`), модуль может быть включен по умолчанию (`enabled = true`).
- Если API требует регистрации ключа (`QUERY_PARAM`, `HEADER`, `BEARER`, `URL_PLACEHOLDER`), поле `apiKey` должно быть пустым (`""`), а сам модуль по умолчанию выключен (`enabled = false`).
- Описание модуля четко указывает возвращаемые поля и тип авторизации.

---

## 03. Сборка и проверка перед отправкой Pull Request

Перед созданием Pull Request выполните полную сборку релизного пакета:

```bash
./gradlew clean assembleDebug assembleRelease lint
```

### Стандарты оформления коммитов
Используйте лаконичные префиксы в стиле Conventional Commits (без эмодзи):
- `feat:` — новая функциональность или новый OSINT-модуль
- `sec:` — улучшения безопасности, криптографии или сетевой фильтрации
- `fix:` — исправление ошибок
- `refactor:` — оптимизация кода без изменения внешнего поведения
- `docs:` — обновление документации и визуальных материалов
